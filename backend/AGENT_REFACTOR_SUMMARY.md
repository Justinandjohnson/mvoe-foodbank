# AI Agent MCP Refactoring Summary

## Overview
All AI agents have been refactored to **exclusively use MCP tools** with **AI doing all analysis and calculations**. No hardcoded business logic remains - agents now orchestrate MCP tools and let AI make all decisions based on real-time data.

---

## Architecture Pattern

### Before (INCORRECT):
```
Agent → Hardcoded methods (generateMenu, calculateSavings, etc.) → Static results
```

### After (CORRECT):
```
Agent → ZenClient (AI planning) → MCP Tools (data collection) → ZenClient (AI analysis) → Results
```

---

## Key Principles

1. **ZenClient** = Helper for direct AI API calls (Anthropic/OpenAI) - used for decision-making
2. **MCP Clients** = Connect to MCP servers (ChromeDevTools, GoogleSheets, USDA, etc.) - used for tool execution
3. **Agents** = Pure orchestrators:
   - Ask AI to create execution plans
   - Call MCP tools based on plans
   - Ask AI to analyze results
   - NO hardcoded business logic
   - NO utility calculation methods

## Example Flow: MealPlannerAgent

### Old Flow (INCORRECT):
```
1. User requests meal plan
2. Agent calls hardcoded generateMenu()
3. Static menu items returned (hamburgers, buns, etc.)
4. Agent calls hardcoded estimateItemCost()
5. Returns hardcoded price estimates ($2.50, $0.30, etc.)
```

### New Flow (CORRECT):
```
1. User requests meal plan
2. Agent asks AI (via ZenClient) for execution plan
3. AI decides to call: zen_plan_meal, usda_analyze_nutrition, chrome_research_prices
4. Agent calls ZenClient.planCommunityMeal() → AI generates menu
5. Agent calls Chrome MCP.researchBulkPrices() → Gets REAL prices from websites
6. Agent asks AI to analyze results and calculate optimal cost
7. AI does math on actual data, returns analysis
```
